## 硬件配置
- MCU: STM32F103C8T6
- OLED: 1.3寸 SH1106 (I2C, PB8=SCL, PB9=SDA, 地址 0x78)
- 舵机: 4路 (TIM2, PA0-PA3)
- 尾巴舵机: 1路 (TIM3_CH1, PA6)
- LED呼吸灯: 2路 (TIM3_CH3=PB0, TIM3_CH4=PB1)
- 语音模块: USART1 (PA9/PA10, 9600)
- 蓝牙: USART3 (PB10/PB11, 115200) — **2026-07-31 已停用, 改 WiFi**
- 电量检测: ADC (PA4)
- WiFi: **USART3 硬件串口 (PB10=TX + PB11=RX, 9600bps)** — 原为软串口(PB6/PB7+TIM4), 已迁移
- 2026-08-02 更新: 外部接 **ESP32-S3** (H11飞线) + **MAX98357A I2S功放** + 喇叭 (AI语音播放)
- 库类型: 标准库 (SPL)

### 27. WiFi 验证 + LittleFS 修复 ✅ (2026-08-10 晚)
- **WiFi 验证通过**: 复位 ESP32 后抓启动日志 `WiFi connected, IP: 172.20.10.2`;Windows ping 通(198-296ms)。服务器 /health 正常(PID 27548,监听 0.0.0.0:8000)
- **发现并修复 LittleFS 挂载失败**: 启动日志 `Corrupted dir pair at {0x0,0x1}, mount failed (-84)`。根因: huge_app 分区方案里 1MB SPIFFS 分区**从未格式化**(全0xFF), 首次 begin() 失败且代码只打印不处理。TTS mp3 要先存 LittleFS 才能播放 → 此 bug 会挡死 AI 语音
- **修复**: `esp32_ai_pet.ino` setup() 中 mount 失败 → `LittleFS.format()` + 重试 begin(UTF-8 文件可直接改, 不像 PetAction.c 是 GBK)。编译 1185055 B (37%), 烧录后日志 `[FS] LittleFS OK` ✅
- 新固件: `D:\pet-ai-server\firmware\` (旧版备份 backup-2026-08-10/ + v5-no-mic-backup/)
- **PSRAM 诊断结论 (无害, 不修)**: 报错链 = 固件按 Octal PSRAM(OPI)编译 → Octal PSRAM 要求 Flash 走 QIO → 本板 Flash 切不了 QIO (`Failed to set QIE bit`) → PSRAM 初始化失败。当前固件全局变量仅 47KB, 内部 SRAM 够用, 固件根本不依赖 PSRAM, 报错后系统继续正常运行。boards.txt 默认已是 OPI(menu.PSRAM.default.build.psram_type=opi)
- **抓 ESP32 串口方法 (改进版)**: esptool 复位会和监听抢 COM 口 → 改用 .NET 直接翻 RTS/DTR 复位 CH343 自动复位电路: RTS=true(EN拉低) 120ms → RTS=false(EN释放) 后立刻连续读。脚本: `D:\pet-ai-server\reset_and_capture.ps1 COM14 out.log 30`
- **烧录路径坑**: 跨 WSL 调用 esptool, exe 用 WSL 路径 (/mnt/c/...), 但 bin 文件参数必须用 Windows 路径 (D:\...) 否则 Permission denied
